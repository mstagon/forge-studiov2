1. 큰 그림 — 3계층 모델

Forge Studio (Electron 앱) 가 워크스페이스를 만들고 그 안에 .claude/ 하네스를 복사한다. Claude Code 가 그 워크스페이스에서 세션을 시작하면 하네스의 룰/스킬/훅이 매 도구 호출마다 끼어들어 작업을 통제한다.

Layer Diagram
핵심 결정: Forge Studio 자체는 Claude 행동에 직접 개입하지 않는다. 단지 하네스를 정확한 자리에 깔아주고, 결과물 (파일/팀/그래프) 을 실시간 시각화할 뿐. 모든 통제는 .claude/ 안의 룰/훅/스킬이 한다.

2. .claude/ 안의 8개 슬롯

하네스의 모든 동작은 이 8개 슬롯의 조합. 각각이 \"언제\", \"어떻게\" 발화하는지가 하네스의 정체.

agents/ 18개

서브에이전트 정의 — flutter-ui, nestjs-backend, prisma-data, code-reviewer 등. 메인 세션이 \"Agent Routing\" 표 매칭 시 파견.

자동 발화: 메인 분석 → 매칭 → Agent() 호출
skills/ 25개

freezed-models, dio-retrofit, mobile-design 등 도메인 패턴. skill-injector.sh 가 파일 경로 매칭 시 SKILL.md 절대경로를 컨텍스트로 주입.

자동 발화: PreToolUse Write/Edit + 파일 패턴
commands/ 25개

/verify, /review, /checkpoint, /implement, /full-cycle 등 슬래시 커맨드. 사용자 입력 또는 워크플로 자동 트리거.

발화: 사용자 입력 OR 파이프라인 자동
rules/common/ 8개

architecture, coding-style, git-workflow, security, testing, orchestration, mcp, automation. CLAUDE.md 의 @-syntax 로 매 세션 자동 컨텍스트 주입.

자동 발화: 매 세션 시작 (mandatory)
scripts/ 10개

훅 셸 스크립트 — gateguard, skill-injector, mcp-health, learn, evaluate-session, auto-profile 등. settings.json 의 hooks 가 호출.

발화: SessionStart / PreToolUse / Stop 등
contexts/

tech-stack.md 등 도메인 컨텍스트. CLAUDE.md 또는 에이전트가 필요 시 Read 로 가져감.

발화: 에이전트가 명시적 Read
mcp.json 15개

MCP 서버 설정 — context7, code-review-graph, dart, serena, supabase, playwright 등. 세션 시작 시 자동 spawn.

발화: 세션 시작 시 자동 + 도구 호출 시
settings.json

model · effortLevel · permissions (allow / deny) · hooks 매핑. 세션 시작 시 로드. Hook profile 이 브랜치별 자동 전환.

발화: 세션 시작 + auto-profile.sh 갱신

3. Hook 라이프사이클

Claude Code 의 5개 라이프사이클 이벤트마다 settings.json 의 hooks 가 fire. PreToolUse 가 핵심 — stdout 은 컨텍스트로 주입되고, exit 2 는 도구를 차단하면서 stderr 를 Claude 에게 피드백.

strict

5. 자동 오케스트레이션 파이프라인

사용자 \"~~ 만들어줘\" 한 줄 → CLAUDE.md 매니저 모드가 분석/위임/검증/리뷰/문서/체크포인트까지 자동으로 진행. 사용자에게 묻는 건 마지막 \"커밋할까요?\" 뿐.

10-step Auto Pipeline (예: \"회원가입 만들어줘\")
01
분석

영향 스택 (Prisma+NestJS+Flutter) + 필요 에이전트 + 의존성 + 적용 스킬 자동 결정.

02
TDD 테스트 먼저

test-writer 자동 파견 → 실패하는 테스트 작성 (Red).

03
구현 (병렬/순차)

의존성 순서: prisma-data → nestjs-backend → flutter-* (병렬, worktree 격리). 테스트 통과 (Green).

04
리팩토링

refactor-cleaner 자동 — 중복/데드코드 정리, 테스트 유지.

05
검증 (/verify)

flutter analyze + test + npm test + lint + DTO 동기화 + 품질 평가.

06
실패 시 자동 수정

loop-operator 자동 — 빌드/테스트 실패 → 수정 → 재검증 (최대 5회).

07
리뷰 3종 동시

code-reviewer + security-auditor + spec-verifier 병렬 파견.

08
문서 동기화 (/update-docs)

API 문서 / dartdoc / CHANGELOG 자동 갱신.

09
체크포인트 (/checkpoint)

피처 완료 시점 자동 백업.

10
"커밋할까요?" 묻기

이것만 사용자에게 묻는다. 답하면 한국어 메시지 + Conventional Commits + Co-Author 차단 검증 통과 후 커밋.

6. 팀 시스템 — Run vs Composition

v0.4.0 의 가장 큰 구조 변화. 기존 단일 \"Team\" 개념을 두 정체성으로 분리. Run = 워크스페이스 안에서 진행 중인 인스턴스, Composition = 글로벌 재사용 템플릿.

Run 워크스페이스 스코프

이 워크스페이스에서 실제로 돌아가는 N명 agent + worktree + 진행도. <wsPath>/.claude/teams/<id>/config.json 에 저장.

필드

id · name · goal · members[] · worktreeStrategy · mergeStrategy · workspaceId · createdAt · status · progress

UI 위치

Workspace 패널 좌측 \"Teams\" 섹션 → 카드 클릭 → 풀스크린 RunLiveView

Composition 글로벌 템플릿

\"이런 멤버 조합으로 일하는 패턴\" 재사용 단위. ~/.claude/team-compositions/<name>.json 에 저장.

필드

name · members[] · defaultWorktree · defaultMerge · usedCount

UI 위치

Library 사이드바 → Compositions 탭 카드 그리드 → \"Apply to workspace\" 클릭 → Wizard 가 멤버 prefilled 상태로 열림

왜 분리했나? Run 은 git worktree 에 묶여 한 워크스페이스 안에서만 의미 있고, Composition 은 \"다음 프로젝트에서 또 쓰고 싶은 멤버 조합\" 이라 글로벌이어야 한다. 이전엔 둘이 한 개념이라 \"이 팀이 어느 프로젝트?\" 매번 헷갈림.

워크스페이스 격리 효과

workspace switch → AgentTeamWatcher.setWorkspace 자동 트리거

8. Run 라이브뷰 — 풀스크린 작업 모니터

Workspace 패널의 Run 카드 클릭 시 메인 영역 전체가 풀스크린으로 전환. 4영역 레이아웃 — 멤버 사이드바, tmux split grid, Activity feed, 컨트롤 바. ESC 로 복귀.

RunLiveView Layout

멤버 카드 클릭 → 그 agent 의 pane 이 grid 에서 강조/확대. 더블클릭 → 풀스크린, ESC 로 그리드 복귀. Activity feed 항목 클릭 → 해당 파일 diff 인라인 표시. 컨트롤 바: Pause All / Resume / Merge (충돌 시 충돌 해결 뷰) / Close.

9. 강제 메커니즘 — 4계층

CLAUDE.md 의 매니저 모드 + 자동 라우팅 표 + Hook 의 stdout 주입 + Bash hook 의 차단/검증. 4개가 합쳐져서 사용자가 한 줄 입력 → 적절한 에이전트가 적절한 스킬로 적절한 코드를 적절한 형식으로 커밋하게 만든다.

Layer 1
매니저 모드

CLAUDE.md ROLE 블록이 메인 세션을 강제. \"5줄 이상 코드 → 위임\", \"방법 설명 전 라우팅\" 등 stop-the-line 4종.

적용 시점

매 응답 시작 시 자가점검 (internal, 출력 X)

Layer 2
자동 라우팅

CLAUDE.md 의 Agent Routing 표 + Skill Routing 표 + Hook Routing 표. 사용자 요청 패턴 → 자동 액션 매핑.

적용 시점

매 사용자 입력 분석 시

Layer 3
강제 주입 (stdout)

skill-injector.sh + gateguard.sh 가 매칭된 SKILL.md / 조사 체크리스트를 컨텍스트에 직접 삽입. 무시 불가.

적용 시점

매 Write/Edit 도구 호출 직전

Layer 4
차단 / 검증

PreToolUse Bash 인라인 — 위험 명령/시크릿/-A·-am/Conventional/한국어/Co-Author 검증. exit 1 (즉시) 또는 exit 2 (재시도 유도).

적용 시점

매 Bash 도구 호출 직전

Bash hook 7단계 검증 (예: git commit)

위험 명령 rm -rf, reset --hard, push --force, --no-verify, prisma db push exit 1
시크릿 패턴 staged 파일에 AKIA..., ghp_..., sk-..., api_key= 등 exit 1
-A / -am 한 방 git add -A && git commit 또는 git commit -am 차단 exit 2
Conventional Commits type(scope): subject 형식 미준수 exit 2
한국어 subject subject 에 한글 1자 이상 없으면 차단 exit 2
Co-Author trailer Co-Authored-By: Claude, 🤖 Generated with Claude 등 exit 2
통과 위 6개 모두 통과 exit 0
exit 1 vs exit 2: exit 1 = 즉시 실패 (Claude 가 완전히 멈춤). exit 2 = 도구 차단 + stderr 를 Claude 컨텍스트로 피드백 → Claude 가 사유 보고 자동 재시도. 사용자 개입 없이 \"한국어 메시지로 다시\" 같은 자동 정정이 가능한 이유.

10. Code Review Graph 통합 (v0.4.0)

11. 자기 개선 루프 — Continuous Learning v2

세션이 끝날 때마다 Stop hook 4종이 fire. 사용자 발언/Claude 행동에서 패턴을 추출 → 신뢰도 평가 → 3회+ 확인되면 instinct → SKILL 로 자동 승격. 만료된 instinct 는 prune.
