# Architecture Rules — 범용 (스택 무관)

이 프리셋은 특정 프레임워크를 가정하지 않는다. 어떤 코드베이스든 아래 원칙 적용.

## 원칙

- **단방향 의존**: 표현 → 도메인 → 인프라. 역방향 import 금지.
- **경계 명시**: 모듈/패키지 간 공개 표면은 최소로 — 내부 구현에 직접 의존 금지.
- **계약 우선**: 모듈 간 인터페이스가 바뀌면 `contracts/` 에 계약 먼저 갱신.
- **테스트 가능성**: I/O (네트워크/DB/파일) 는 경계 뒤로 — 핵심 로직은 순수하게.
- **기존 패턴 우선**: 새 코드는 그 코드베이스의 기존 컨벤션을 따른다.
  첫 작업 전 `contexts/tech-stack.md` 를 실제 스택으로 채우고 그걸 기준으로.

## 변경 시 체크

1. 이 변경이 어느 레이어 소속인가? 레이어를 넘나들면 분리.
2. public 표면 변경인가? 호출부 영향 + contracts 갱신.
3. 테스트가 같은 레이어에 존재하는가?
