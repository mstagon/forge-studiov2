# Eval Harness

구현 결과를 기준 대비 평가하는 프레임워크.

## 평가 기준

### 코드 품질 (40%)
- [ ] 타입 안전성 (any/dynamic 없음)
- [ ] 에러 핸들링 (Result 패턴 또는 try-catch)
- [ ] 로깅 (print/console.log 대신 logger)
- [ ] 네이밍 컨벤션 준수
- [ ] 코드 중복 없음

### 테스트 (25%)
- [ ] 단위 테스트 존재
- [ ] 핵심 경로 테스트 커버
- [ ] 엣지 케이스 테스트
- [ ] 테스트 전체 통과

### 아키텍처 (20%)
- [ ] 레이어 규칙 준수 (단방향 의존)
- [ ] 단일 책임 원칙
- [ ] 적절한 추상화 수준
- [ ] 크로스 스택 계약 일치

### 보안 (15%)
- [ ] 인증/인가 체크
- [ ] 입력 검증
- [ ] SQL/XSS 인젝션 방지
- [ ] 시크릿 노출 없음

## 점수 산정

```
총점 = (코드품질 × 0.4) + (테스트 × 0.25) + (아키텍처 × 0.2) + (보안 × 0.15)

A: 90-100 — 프로덕션 준비 완료
B: 80-89  — 마이너 개선 후 배포 가능
C: 70-79  — 주요 항목 수정 필요
D: 60-69  — 대폭 수정 필요
F: <60    — 재구현 고려
```

## 사용법

```
/eval                    # 현재 변경사항 평가
/eval --baseline specs/  # 스펙 대비 평가
/eval --compare HEAD~5   # 이전 커밋 대비 평가
```
